## 一、使用规则

1. **随时记录**：每次做题、测验暴露出的错误，立即登记到"错误总表"。
2. **编号管理**：每个错误分配唯一编号 `ERR-XXX`，方便追踪。
3. **检验升级**：按"间隔复习检验方案"定期检验，通过则标记 ✅。
4. **升降级规则：**
   - 连续 **2 次** 检验通过 → 状态升级为 ✅ 已掌握
   - 已掌握后**再次犯错** → 状态降级为 🔄 复发，重新走检验周期

| 状态 | 含义 |
|------|------|
| 🔴 新发现 | 刚记录，还没检验过 |
| 🟡 复习中 | 已检验 1 次以上，尚未完全掌握 |
| 🔄 复发 | 已掌握过，但又犯错了 |
| ✅ 已掌握 | 连续 2 次检验通过 |

## 三、错误详细卡片

> 每张卡片包含：错误写法 → 正确写法 → 原因 → 记忆口诀。

### ERR-001 · 变量未定义就使用

- ❌ **错误写法：**
  ```java
  int need = target - num;   // num 不存在！编译报错
  map.put(num[i], i);        // 应为 nums[i]
  ```
- ✅ **正确写法：**
  ```java
  int num = nums[i];          // 先定义局部变量
  int need = target - num;    // 再用
  // 或直接：
  int need = target - nums[i];
  map.put(nums[i], i);
  ```
- 📖 **为什么错：** Java 是强类型语言，**变量必须先定义（声明）再使用**。`nums` 是方法参数（数组），而 `num` 从来没人定义过。
- 🧠 **口诀：** 变量就像门牌号，**先挂牌，再敲门**。

---

### ERR-002 · `Array` vs `Arrays`（工具类带 s）

- ❌ **错误写法：**
  ```java
  Array.sort(arr);   // 编译错误：没有 Array 这个类
  ```
- ✅ **正确写法：**
  ```java
  Arrays.sort(arr);  // 工具类叫 Arrays（复数，带 s）
  ```
- 📖 **为什么错：** Java 中操作数组的工具类是 `Arrays`（在 `java.util` 包中）。它叫"数组们"（复数），所以带 `s`。同理还有 `Collections`（集合们的工具类）、`Objects`。
- 🧠 **口诀：** 工具类都是"一群人" → 复数 → 带 **s**。`Array` 只是"单个数组"的概念词，不是类名。

---

### ERR-003 · `get` vs `containsKey`

- ❌ **错误写法：**
  ```java
  if (!map.get(key)) {          // 编译错误！List 不能取反
      map.put(key, new ArrayList<>());
  }
  ```
- ✅ **正确写法：**
  ```java
  if (!map.containsKey(key)) {  // 问"有没有这个 key"
      map.put(key, new ArrayList<>());
  }
  ```
- 📖 **为什么错：** `get(key)` 返回的是 **value**（这里是 `List<String>`，一个列表对象），不是布尔值，不能 `!` 取反。想"判断 key 是否存在"，要用 `containsKey(key)`（返回 `true/false`）。
- 🧠 **口诀：** 一个问"**有没有**"，一个问"**值是什么**"。
  - `containsKey` → 保安：这个 key 在不在？→ 在/不在（true/false）
  - `get` → 库管：这个 key 对应什么？→ 拿出 value

---

### ERR-004 · 增强 for 循环缺类型声明

- ❌ **错误写法：**
  ```java
  for (str : strs) {   // 编译错误：str 是什么类型？
  ```
- ✅ **正确写法：**
  ```java
  for (String str : strs) {   // 必须写明元素类型
  ```
- 📖 **为什么错：** 增强 for（for-each）的语法是 `for (元素类型 变量名 : 集合/数组)`，**类型必须显式声明**。编译器需要知道 `str` 是 `String` 才能调用 `str.toCharArray()`。
- 🧠 **口诀：** for-each 三件套缺一不可：**类型 · 变量 · 冒号 · 数组** → `for (类型 变量 : 数组)`。

---

### ERR-005 · `int[]` ≠ `List` + `Arrays.asList()` 用法

- ❌ **错误写法：**
  ```java
  Set<List<Integer>> set = new HashSet<>();
  set.add(new int[]{1, 2, 3});   // 编译错误：int[] 不是 List<Integer>
  ```
- ✅ **正确写法：**
  ```java
  set.add(Arrays.asList(1, 2, 3));   // 用 Arrays.asList 包装成 List
  // 或等价写法：
  set.add(Arrays.asList(nums[i], nums[left], nums[right]));
  ```
- 📖 **为什么错：**
  1. `int[]`（数组）和 `List<Integer>`（列表）是**两种不同的类型**，不能混用
  2. `List<Integer>` 能存 `int`，靠的是**自动装箱**（int → Integer），但这不代表 `int[]` 就是 `List`
  3. `Arrays.asList(...)` 的作用：把**可变参数**包装成一个**定长 List**
- 🧠 **口诀：** 数组是数组，列表是列表，`asList` 是"包装"不是"拷贝"。
- 📌 **Arrays.asList 的三个坑：**
  1. **返回定长 List**：不能 `add()` / `remove()`，否则报 `UnsupportedOperationException`
  2. **底层还是原数组**：改 list 会改原数组，改数组也会改 list（视图不是拷贝）
  3. **基本类型数组大坑**：`Arrays.asList(intArray)` 会把整个 `int[]` 当成**一个元素**，得到 `List<int[]>` 而不是 `List<Integer>`！要用包装类型 `Integer[]` 或逐个转
- 🔧 **想变成可变 List？** `new ArrayList<>(Arrays.asList(...))` — 重新拷贝一份，可增删
- 💡 **Java 9+ 更优选择：** `List.of(1, 2, 3)` — 更简洁，同样不可变

### ERR-006 · 滑动窗口 4 个坑（组合坑）

- ❌ **坑 1：循环条件方向写反**
  ```java
  for (int right = 0; right > s.length(); right++)   // ❌ 永不执行
  for (int right = 0; right < s.length(); right++)   // ✅
  ```
- ❌ **坑 2：只在"重复时"更新答案**
  ```java
  if (set.contains(ch)) { maxlen = Math.max(...); }   // ❌ 无重复时返回 0
  maxlen = Math.max(maxlen, right - left + 1);        // ✅ 每次扩展后都更新
  ```
- ❌ **坑 3：收缩用 if 而不是 while**
  ```java
  if (set.contains(ch)) { remove 一个; left++; }      // ❌ 可能收不干净
  while (set.contains(ch)) { remove; left++; }        // ✅ 收到没有重复为止
  ```
- ❌ **坑 4：长度公式忘 +1 / remove 顺序反**
  ```java
  right - left                                     // ❌ 少算 1
  right - left + 1                                 // ✅ 闭区间长度
  left++; set.remove(s.charAt(left));              // ❌ 移错字符（先++再删）
  set.remove(s.charAt(left)); left++;              // ✅ 先删再++
  ```
- 📖 **为什么错：** 滑动窗口的核心是"**每次扩展窗口后，窗口都是合法的，再更新答案**"。收缩必须"收干净"（while），答案必须"每次都算"（防止无重复时漏算）。
- 🧠 **口诀：** 右扩左收 while 净，每扩一档更新答案，长度闭区间 +1。

### ERR-007 · 基础语法手滑（5 连坑）

- ❌ **坑 1：`charAt` 记成 `atChar`**（中文语序"位置i的字符" → 英文语序"字符在位置i"）
  ```java
  p.atChar(i)     // ❌
  p.charAt(i)     // ✅ char(C小写) + At(A大写)
  ```
  > 🧠 记忆：Java 方法名是"**东西 + 动作**"：`char`(字符) + `At`(在位置)。默念"**字符·在·位置**"。

- ❌ **坑 2：`p.length` 忘括号**
  ```java
  p.length        // ❌ 编译错误
  p.length()      // ✅ String 是对象，用方法 length()
  ```
  > 🧠 记忆：**对象用方法带括号**，**数组用字段没括号**：`"abc".length()` vs `arr.length`

- ❌ **坑 3：`False` / `True` 大写**
  ```java
  return False;   // ❌
  return false;   // ✅ Java 关键字全小写
  ```

- ❌ **坑 4：数组参数忘 `[]`**
  ```java
  public static boolean areEqual(int cntP, int cntS)   // ❌
  public static boolean areEqual(int[] cntP, int[] cntS)  // ✅
  ```
  > 🧠 记忆：**数组类型声明必须带 `[]`**，不分参数还是局部变量。

- ❌ **坑 5：滑窗滑入方向写反**
  ```java
  window[s.charAt(left + p.length()) - 'a']--;   // ❌ 右边滑入应++
  window[s.charAt(left + p.length()) - 'a']++;   // ✅ 滑入加、滑出减
  ```
  > 🧠 口诀：**滑出减、滑入加**。

### ERR-014 · 螺旋矩阵漏边界检查（重复遍历）

- ❌ **错误写法：**
  ```java
  // 走"下边"和"左边"前没有检查边界是否还合法
  for (int j = right; j >= left; j--) res.add(matrix[bottom][j]);  // ❌
  bottom--;
  for (int i = bottom; i >= top; i--) res.add(matrix[i][left]);   // ❌
  left++;
  ```
- ✅ **正确写法：**
  ```java
  // 走"下边"前检查 top <= bottom（防只剩一行重复）
  if (top <= bottom) {
      for (int j = right; j >= left; j--) res.add(matrix[bottom][j]);
      bottom--;
  }
  // 走"左边"前检查 left <= right（防只剩一列重复）
  if (left <= right) {
      for (int i = bottom; i >= top; i--) res.add(matrix[i][left]);
      left++;
  }
  ```
- 📖 **为什么错：** 非方阵或最后一圈只剩一行/一列时，上边和右边已经遍历过那些元素了。如果下边/左边还继续走，会**重复添加已遍历的元素**。
- 🧠 **口诀：** **"下边看上下，左边看左右。"** 走下边前检查 `top <= bottom`，走左边前检查 `left <= right`。
- 💡 **同类场景：** 所有螺旋遍历类题（54 螺旋矩阵、59 螺旋矩阵 II、885 螺旋矩阵 III）。

### ERR-013 · 原地哈希交换死循环（缺保护条件）

- ❌ **错误写法：**
  ```java
  while (1 <= nums[i] && nums[i] <= n) {   // 缺了目标位置判断 → 重复值死循环！
      int correctPos = nums[i] - 1;
      // 交换...
  }
  ```
- ✅ **正确写法：**
  ```java
  while (1 <= nums[i] && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
      //                                    ↑ 目标位置已有相同值 → 不再交换（防死循环）
      int correctPos = nums[i] - 1;
      // 交换...
  }
  ```
- 📖 **为什么错：** 当 `nums[i]` 已经在正确位置（目标位置就是自己，或目标位置已有相同值）时，交换是"自交换"，值不变，while 条件仍满足 → 无限循环。
- 🧠 **口诀：** **"值在范围内 且 目标位置不是我 才交换"**。`nums[nums[i]-1] != nums[i]` 是死循环的刹车。
- 💡 **同类场景：** 所有"原地哈希 + 交换归位"的题（41 缺失正数、287 重复数、448 消失数字）都要带这个保护。

### ERR-012 · 覆盖 vs 叠加（`=` 还是 `*=`）

- ❌ **错误写法：**
  ```java
  // 第二遍扫描时，第一遍的结果要被保留
  res[i] = right;   // ❌ 用 = 把第一遍存的左边积覆盖掉了！
  ```
- ✅ **正确写法：**
  ```java
  res[i] = res[i] * right;   // ✅ 在第一遍基础上叠加右边积
  // 或等价写法：
  res[i] *= right;           // ✅ 叠加
  ```
- 📖 **为什么错：** "两遍扫描"类题目（如前缀积×后缀积），第二遍是在**第一遍的结果上叠加**另一半信息，不是覆盖。用 `=` 会丢掉第一遍的结果。
- 🧠 **判断口诀：** 第二遍要不要保留第一遍？**要 → 用 `*=`（叠加）；不要 → 用 `=`（覆盖）**。
- 💡 **同类场景：** 238 除自身乘积、42 接雨水（两遍扫描）、135 分发糖果——都是"第一遍存，第二遍叠加"。

### ERR-011 · 忘取模 k%=n（轮转/循环类）

- ❌ **错误写法：**
  ```java
  reverse(nums, 0, k - 1);   // 直接用了 k，如果 k > nums.length 会越界！
  ```
- ✅ **正确写法：**
  ```java
  int n = nums.length;
  k %= n;                     // 先取模！
  if (k == 0) return;
  reverse(nums, 0, k - 1);
  ```
- 📖 **为什么错：** 轮转/循环类题目中，操作 `k` 次等于操作 `k % n` 次（转满一圈没变化）。k 可能远大于 n，不取模会导致数组越界或结果错误。
- 🧠 **口诀：** **"轮转先取模"**。看到"轮转/循环/步长 k"的题，第一步先 `k %= n`。
- 💡 **同类场景：** 轮转数组、旋转链表、环形数组、循环队列——凡是 k 表示"步数"的都要考虑取模。

### ERR-009 · 数组索引用错（窗口下标 vs ASCII 码）

- ❌ **错误写法：**
  ```java
  cntS[left++]--;   // left 是窗口下标（0,1,2...），不是字符的 ASCII 码！
  ```
- ✅ **正确写法：**
  ```java
  cntS[S.charAt(left++)]--;   // 要用字符的 ASCII 码做索引
  ```
- 📖 **为什么错：** `cntS` 这个计数数组是用**字符的 ASCII 码**做下标（如 'A'=65, 'a'=97）。而 `left` 是窗口位置下标（0,1,2...），两者不是一回事。用 `left` 当索引，计数彻底错乱。
- 🧠 **口诀：** **计数数组用字符下标，窗口位置用 left。** 从窗口里删字符，要 `cntS[字符]--`，不是 `cntS[left]--`。

---

### ERR-010 · 覆盖语义用错（涵盖 = 大于等于）

- ❌ **错误写法：**
  ```java
  if (cntS[i] != cntT[i]) return false;   // 要求"完全相等"才覆盖
  ```
- ✅ **正确写法：**
  ```java
  if (cntS[i] < cntT[i]) return false;    // 只要有一个"不够"就不覆盖
  ```
- 📖 **为什么错：** "涵盖"（cover）允许窗口里**多出** t 之外的字符，只要每个需要的字符数量 **≥** 需求即可。用 `!=`（完全相等）会把"多了字符"的情况误判为未覆盖，导致永远找不到答案。
- 🧠 **口诀：** 覆盖 = **每个字符 ≥ 需求**。不是相等，是"只少不多"。

### ERR-008 · if vs while 用错（"删干净"问题）

- ❌ **错误写法：**
  ```java
  if (q.peekLast() < nums[i]) {   // ❌ 只弹出一个
      q.removeLast();
  }
  ```
- ✅ **正确写法：**
  ```java
  while (!q.isEmpty() && q.peekLast() < nums[i]) {   // ✅ 弹出所有比它小的
      q.removeLast();
  }
  ```
- 📖 **为什么错：** 单调队列里，新元素 `nums[i]` 来了，要**淘汰所有**比它小的旧元素（它们都当不了最大）。`if` 只执行一次，只删掉最后一个，留下的小元素会被错误地当成候选。用 `while` 才能删到"队尾不小于新值"为止。
- 🧠 **判断口诀：** 遇到"**删除所有满足条件的**"（比如所有比 x 小的）→ 用 `while`；遇到"**只处理一个**" → 用 `if`。
- 💡 **同类场景：** 滑动窗口收缩、单调栈、回溯去重里，凡是"一直删到条件不满足为止"都要 `while`。

### ERR-015 · 链表判"同一节点"用引用 `==` 不是 `.val ==`

- ❌ **错误写法：**
  ```java
  if (maxlen.val == minlen.val) {   // 比的是"值"，不是"是不是同一个节点"
      return maxlen;
  }
  ```
- ✅ **正确写法：**
  ```java
  if (maxlen == minlen) {   // 比引用：两个引用是否指向同一个对象
      return maxlen;
  }
  ```
- 📖 **为什么错：** 链表"相交"= 两个链表**共享同一个节点对象**（同一个 `ListNode` 实例）。值相等只能说明"长得像"，不代表是同一个节点。反例：`A: 1→2→3`、`B: 5→3→9`，两个 3 的值一样但不同对象，并没有相交。
- 🧠 **口诀：** **"链表认人不认脸。"** 判同一个节点用 `==`（认地址），判数值才用 `.val ==`。
- 💡 **同类场景：** 160 相交链表、141/142 环形链表、链表去重——只要判断"是不是同一个节点"，全部用 `==`。

### ERR-016 · 链表题的 Java 语法连锁坑

- ❌ **坑 1：`while(curA)` 对象不能当 boolean**
  ```java
  while (curA) { ... }   // ❌ Java 编译错误，条件必须是 true/false
  while (curA != null)   // ✅
  ```
- ❌ **坑 2：`min()` 不是函数，是 `Math.min()`**
  ```java
  for (i < min(lengA, lengB))   // ❌ 没有这个函数
  Math.min(lengA, lengB)        // ✅ 工具方法都在类里
  ```
- ❌ **坑 3：块作用域——花括号里声明的变量，外面用不了**
  ```java
  if (a > b) {
      ListNode maxlen = headA;   // ❌ 离开 if 花括号就消失
  }
  maxlen.next;                    // ❌ 编译错误：找不到变量
  ```
  应改为：**先在 if 外面声明，里面只赋值**。
- ❌ **坑 4：复制粘贴忘改变量名**
  ```java
  while (curB != null) {
      curA = curB.next;   // ❌ 应为 curB = curB.next，导致 curB 永不走 → 死循环
  }
  ```
- 🧠 **口诀：** **"循环条件要 boolean、工具方法带类名、变量声明在外面、复制粘贴改名字。"**
- 📖 **为什么错：** 这些不是算法问题，是 Java 基本功。写链表题时脑子集中在逻辑上，容易忽略语法细节。

### ERR-017 · LRU 双向链表 4 连坑

- ❌ **坑 1：get 漏 return → 永远返回 -1**
  ```java
  if (map.containsKey(key)) {
      int res = map.get(key).value;   // 算了 res
      moveToHead(map.get(key));
  }
  return -1;                          // ❌ 找到也返回 -1
  ```
  ✅ **正确写法：**
  ```java
  if (map.containsKey(key)) {
      DNode node = map.get(key);
      moveToHead(node);
      return node.value;              // ✅ 找到就返回，找不到才 -1
  }
  return -1;
  ```

- ❌ **坑 2：新节点也 moveToHead → 空指针**
  ```java
  DNode node = new DNode(key, value);  // 新节点 pre/next 都是 null
  moveToHead(node);                    // ❌ moveToHead 先摘除 → node.pre.next 空指针！
  ```
  ✅ **正确写法：新节点用 addToHead（只插不摘），老节点才 moveToHead（先摘再插）**
  ```java
  private void addToHead(DNode node) {   // 新节点用这个
      node.pre = head; node.next = head.next;
      head.next.pre = node; head.next = node;
  }
  private void moveToHead(DNode node) {  // 已在链表中的节点才用这个
      removeNode(node);
      addToHead(node);
  }
  ```

- ❌ **坑 3：put 漏处理"key 已存在" → 孤儿节点**
  ```java
  // 每次都新建 → 链表里出现两个相同 key 的节点，旧节点成孤儿，链表越拉越长
  ```
  ✅ **正确写法：**
  ```java
  if (map.containsKey(key)) {
      DNode node = map.get(key);
      node.value = value;      // 只更新值
      moveToHead(node);        // 移到头部
      return;
  }
  ```

- ❌ **坑 4：removeTail 漏删 map → 幽灵值**
  ```java
  private void removeTail() {
      DNode node = tail.pre;
      node.pre.next = tail;
      tail.pre = node.pre;
      // ❌ 漏了 map.remove(node.key)
  }
  ```
  ✅ **正确写法：**
  ```java
  private void removeTail() {
      DNode node = tail.pre;
      node.pre.next = tail;
      tail.pre = node.pre;
      map.remove(node.key);    // ⭐ 链表和 map 两个系统必须同步删（REV-23）
  }
  ```

- 🧠 **口诀：** **"get 要 return、新节点 addToHead、put 先查存在、删链同步删 map。"**
- 📖 **为什么错：** LRU = HashMap + 双向链表两个系统联动。每个操作都要想清楚：①返回值 ②这个节点在不在链表里 ③key 是否已存在 ④链表和 map 是否同步。漏任何一环都会出幽灵值或空指针。
- 💡 **同类场景：** 所有"Map + 链表/树联动"的题（LRU、LFU、TreeMap 相关）都要注意"双系统同步"。

### ERR-018 · BFS 层序遍历 5 连坑

- ❌ **坑 1：`new ArrayList<>()` 当 Deque**
  ```java
  Deque<TreeNode> deque = new ArrayList<>();   // ❌ 编译错误
  ```
  ✅ `ArrayList` 实现的是 `List` 不是 `Deque`。Deque 的常用实现：
  ```java
  Deque<TreeNode> queue = new ArrayDeque<>();  // ✅
  ```

- ❌ **坑 2：add / offer 混用**
  ```java
  queue.add(root);      // ❌ add 是抛异常版
  queue.offer(root);    // ✅ 返回特殊值版，刷题统一用它
  ```
  > 📖 方法命名总纲（REV-25）：add/remove/element = 抛异常版；offer/poll/peek = 返回特殊值版。刷题统一用后者。

- ❌ **坑 3：for 条件里 `queue.size()` 会变**
  ```java
  for (int i = 0; i < queue.size(); i++)   // ❌ 循环里入队会让 size 变大
  ```
  ✅ 必须先固定当前层人数：
  ```java
  int size = queue.size();                  // ✅ 记录"当前层"节点数
  for (int i = 0; i < size; i++) { ... }
  ```

- ❌ **坑 4：`peekFirst()` 只看不弹 → 死循环**
  ```java
  p = queue.peekFirst();   // ❌ 节点永远留在队里
  ```
  ✅ 取出并移除队头用 `poll()`：
  ```java
  TreeNode node = queue.poll();
  ```

- ❌ **坑 5：int 类型调 push → 复制粘贴没改名**
  ```java
  depth.push(node.right);   // ❌ depth 是 int，没有 push 方法（ERR-016 同款）
  ```
  ✅ 应该是右孩子入队：
  ```java
  queue.offer(node.right);
  ```

- 🧠 **口诀：** **"ArrayDeque 建队、offer/poll 一对、size 先固定、peek 不弹出、粘贴改名字。"**
- 📖 **为什么错：** BFS 层序模板虽短，但 Deque 方法不熟 + 复制粘贴惯性导致一堆连锁小错。都是细节，但每个都能让代码跑不起来或死循环。
- 💡 **同类场景：** 所有 BFS 层序遍历（102/199/637 等）、树/图的广度优先搜索。
